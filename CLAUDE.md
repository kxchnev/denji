# denji

Монорепо: библиотека для **архитектурных диаграмм в свободном стиле** +
сайт-документация. Фигуры (app/database/queue/rect), контейнеры (service/group),
связи. **Раскладка автоматическая: её задают связи.** Хинты (`@rightOf`,
`@below`) — ограничения для движка; координат в языке нет вовсе. Стек:
TypeScript, SVG.

## ⚠️ Документация — часть Definition of Done

**Добавили/изменили функциональность ядра → обновили доку-сайт.** Примеры живут в
`packages/docs/examples/*.ts` (единый источник: `{ title, description, dsl, api }`).
Порядок: добавить пример в нужный датасет (elements/arrows/blocks/layout) →
`npm run -w docs validate` (прогон через ядро) должен быть зелёным → при новой
категории добавить страницу и пункт в `packages/docs/lib/nav.ts`.

## Структура (npm workspaces)

```
packages/core/   пакет @kxchnev/denji — библиотека + CLI
packages/docs/   Next.js + shadcn дока с живым playground (зависит от @kxchnev/denji)
packages/vscode/ расширение VS Code: живое превью .denji с драгом
package.json     workspace-root (скрипты-прокси)
```

### packages/core (ядро)

Слои: `DSL (.denji) → Model → Layout (граф + контейнеры) → Router → Renderer → SVG`.

- `src/model/` — `geometry.ts`, `arch.ts` (типы), `arch-builder.ts` (билдер),
  `icon.names.ts` (141 КБ имён и заголовков) — генерируется вместе с артворком
  `scripts/generate-icons.ts` на сборке (`prebuild`/`pretest`/`pretypecheck`),
  **в гите его нет**.
  ⚠️ **Артворк существует дважды, и это плата за совместимость.** Модулем
  (`src/model/icon.data.ts`) — потому что `resolveIcon` синхронный, а браузер не
  умеет читать файл на импорте: только модуль позволяет сдержать обещание «импортнул
  пакет — марки рисуются», которое дали все релизы до 1.2.0. И файлом
  (`assets/icons.json`) — потому что растеризатору со шрифтом всё равно нужны
  байты, а продукт, умеющий прочитать файл, не должен платить за артворк в бандле.
  Обе дороги кончаются в одном реестре (`src/resources.ts`), `resolveIcon`
  спрашивает только его.
  ⚠️ **Побочный эффект — ровно один, в `src/index.ts`**: точка входа регистрирует
  забандленную таблицу. Отсюда `"sideEffects": ["./dist/index.js"]` в
  `package.json` — с `false` сборщик имеет полное право выбросить эту регистрацию
  как ненужную, и совместимость сломается молча и только у части пользователей.
  Кто хочет лёгкий бандл — импортирует подмодули и регистрирует марки сам; так
  живёт CLI, поэтому `denji check` стартует за 0.08 с. Цена решения и то, что мы
  получим, когда от него откажемся, — в `NEXT-MAJOR.md`.
  ⚠️ Имена по-прежнему отдельно от путей: всё, чему нужно лишь *знать* о
  существовании марки — парсер, валидация билдера, подсказка при опечатке —
  ходит в `icon.names.ts`.
  Версия набора записана рядом (`ICONSET_VERSION`). Обновить всё разом —
  `npm run icons:update`.
  ⚠️ Реальная марка всегда бьёт рукописный алиас: `elastic` перестал быть
  сокращением для `elasticsearch` в тот день, когда у Elastic появился свой знак,
  и генератор такие столкновения отбрасывает сам.
- `src/layout/arch/` — `graph.ts` (иерархия + **проекция связей на скоуп**:
  связь между потрохами двух контейнеров — это, снаружи, причина этим контейнерам
  стоять рядом), `auto.ts` (движок: развороты циклов → ранги → минимизация
  пересечений → координаты; там же типы скоупа — `Placeable`, `AxisGaps`,
  `LayoutWarning`), `ports.ts` (двери контейнеров), `route.ts` (роутер связей),
  `index.ts` (оркестрация, bottom-up sizing контейнеров, заполняет `node.local`),
  `measure.ts`.
  ⚠️ Отдельного `scope.ts` больше нет: он существовал, чтобы мирить остров
  прибитых `@at`-узлов с автораскладкой, а мирить стало нечего — скоуп это
  ровно `autoPlace`.
  ⚠️ **Двери, и поэтому два прохода.** Скоуп раскладывался, ничего не зная о
  внешнем мире: связь наружу проецировалась на контейнер целиком, поэтому `biba`
  в глубине `bi` тянулся к `s3` через весь рисунок. `ports.ts` отвечает на «с
  какой стороны у этого контейнера уходит трафик», и ответ берётся из **пробного
  прохода**: `index.ts` кладёт диаграмму дважды, первый раз — чтобы узнать
  сторону. Сторона — грубый факт («infra правее company»), он переживает смену
  всех размеров вторым проходом, поэтому проходов ровно два и они не колеблются.
  ⚠️ **Дверь — обычная вершина скоупа**, нулевого размера и никогда не
  рисуемая (`Vertex.door`): ранжирование, минимизация пересечений и PAVA двигают
  члена сами, второго механизма размещения нет. Дверь поперёк потока приколочена
  к границе, дверь вдоль потока получает свой ранг (слой из одних дверей имеет
  нулевую толщину и нулевые зазоры — иначе каждая внешняя связь раздувала бы
  контейнер на пустую полосу). Пиннинга мало: PAVA не переставляет слой, поэтому
  `applyDoorOrder` ещё и **сортирует** слой по тому, куда узлу надо смотреть —
  без этого `bi` оставался левее `datahub` при двери справа.
  ⚠️ **Дверь снаружи — это `PortOffset`.** `ScopeEdge.pairs` несёт настоящие
  концы связи, а выравнивание сводит не центры коробок, а двери: «сдвинь меня,
  чтобы моя дверь встала против двери на том конце». Отсюда `VS Code` ровно над
  `vscode-server`, а не над серединой группы.
  ⚠️ **Ранг вместо координаты.** `rightOf`/`leftOf` — «тот же слой, в таком
  порядке», `below`/`above` — «слой позже/раньше»; что чем становится, зависит от
  направления потока. Цикл в хинтах роняет замыкающие отношения и даёт
  `hint-cycle`; цикл в **связях** — обычный сервисный граф и молчит.
  ⚠️ **Кластеры перед слоями.** Плоская слоистая раскладка размазывает по всей
  ширине то, что связано между собой. `communities()` (распространение меток,
  детерминированное) режет граф на сообщества, каждое рисуется само, потом
  сообщества раскладываются тем же движком. На реальной диаграмме это 3.7 Мпикс
  против 5.9 и меньше пересечений.
  ⚠️ **Фиктивные узлы — это коридоры.** Ребро через слой занимает в нём место
  наравне с коробками, поэтому в слое остаётся полоса, где коробок нет по
  построению. Раскладка отдаёт её роутеру через `ScopeResult.lanes`.
  ⚠️ Координата поперёк потока — **точное** решение изотонной задачи (PAVA в
  `settleLayer`), а не расталкивание по приоритетам: расталкивание умеет только
  раздвигать, и рисунок растёт от прохода к проходу. Сетка применяется к блоку
  PAVA, а не к узлу: внутри блока смещения — точные суммы размеров и авторских
  `@gap`, и округление узла испортило бы именно их.
  ⚠️ **Размер листа не зависит от его подписи.** `chooseShapeWidths` — плоский
  пред-проход перед рекурсивным `sizeNode`: каждая фигура говорит, какой узкой
  она могла бы быть с подписью в две строки, самый широкий ответ достаётся всем.
  База — ровно на `DB_NARROW` уже (если самое длинное имя у базы, растёт общая
  ширина, а не бочка). Фигура с явным `@width` не берёт общую ширину и не
  участвует в её выборе. Разрыв строки (`bestSplit`) — **чистая функция от
  строки**, не от доступной ширины: поэтому рендер воспроизводит решение
  раскладки из ширины коробки, а число строк — из её высоты; хранить перенос
  негде не нужно. Слово, которому не хватает строки, режется дефисом — иначе
  одно длинное имя задавало бы ширину всей диаграммы (потолок `MAX_SHARED_WIDTH`).
  Высота базы выводится из её ширины (`DB_ASPECT`), а не из текста: по тексту
  она и получалась блином. Очередь выводится из бочки, но
  явно горизонтальная (`QUEUE_SHRINK`/`QUEUE_ASPECT`): просто переставить стороны
  почти квадратной бочки мало — лёжа она остаётся стоячей. У **базы** иконка
  стоит над подписью (`iconAbove`): 26px марки поперёк узкой бочки — это треть
  строки; у очереди запас горизонтальный, и марка остаётся слева.
- `src/layout/arch/route.ts` — обход препятствий и шина. Разрежённый
  ортогональный граф видимости (границы коробок ± зазор, координаты доков и
  коридоров, середины широких промежутков) → A* со штрафом за излом → **nudging**:
  сегменты в одном коридоре упорядочиваются по тому, откуда пришли и куда уходят,
  и разводятся с шагом `BUS_PITCH`. Углы скругляются широко — излом читается как
  кривая, а вход в коробку остаётся перпендикулярным по построению.
  ⚠️ Собственная коробка конца связи **тоже препятствие** (ужатая на зазор,
  `deflate`) — иначе путь режет её насквозь и приходит к своему доку изнутри.
  ⚠️ Шина зажата в свободный коридор (`corridorOf`): пучок шире щели вытолкнул бы
  крайнюю линию ровно в ту коробку, ради обхода которой путь и строился.
  ⚠️ Рамка рисунка считается и по маршрутам (`bounds` в рендере), иначе
  обрезается самый длинный обход — тот, который интереснее всего.
  ⚠️ **Порядок в шине и на стороне коробки — по замеру, а не по правилу.**
  Соседние полосы (`bundle`) и соседние доки (`untangleDocks`) пробуют
  поменяться местами, и обмен принимается, только если пересечений стало меньше;
  у доков пересечение «у самой коробки» весит вдесятеро против далёкого. Обмен
  полос наложения создать не может — набор полос тот же, — поэтому проверяется
  только результат. Догадаться тут нельзя в принципе: куда поедет линия, известно
  только после поиска пути, а сам пучок раньше *создавал* семь пересечений из
  шестнадцати.
  ⚠️ **Ствол — плотный пучок, а не одна линия.** Связи с общим концом идут с
  `TRUNK_PITCH` (6) вместо `BUS_PITCH` (8), и **стрелки входят тем же шагом**:
  гребёнка 24px на пять входов вместо 56. Что этому мешало — сегмент с доком
  неподвижен (сдвинешь — оторвёшь стрелку от коробки); внутри ствола ему можно,
  потому что **док съезжает вместе с ним** по своей же стороне. Пучок, который
  стволом не является (линии приходят с разных концов рисунка), держит полный шаг:
  иначе каждой пришлось бы шагать в сторону перед наконечником. Порядок:
  развязка → выпрямление хвостов → связывание стволов → выпрямление **ещё раз**,
  уже вдоль стволов; поэтому доки переезжают, а мелких шагов не остаётся.
  ⚠️ **Последний мелкий шаг уходит в док** (`straightenApproach`). Линия шла
  прямо двести пикселей и уходила на 8px в сторону в последних двадцати —
  дрожь ровно у наконечника, где читателю важнее всего. Правило «считать доки
  иначе» чинит эту линию и двигает двадцать других, поэтому правка делается
  **после** прокладки и по одному доку: приезжающий док съезжает на линию, по
  которой маршрут пришёл, и только если это **бесплатно** — он остаётся на своей
  стороне, держит `MIN_DOCK_PITCH` от соседей (те не двигаются), новый прямой
  участок чист от коробок, и рисунок не получает ни пересечения, ни сдвоенной
  линии. Путь обязательно `simplify` — два коллинеарных сегмента шина растащит
  как два, и «прямая» выйдет диагональю. Оба конца, но **приёмный первым**: если
  прямым может быть только один, это должен быть тот, куда смотрят, когда линия
  приходит.
- `src/export.ts` — **единственная дорога от диаграммы к файлу**, и её берут все
  три продукта: `toSvgFile` / `toPng` / `toJpeg`. Отсюда «одна диаграмма — одна
  картинка везде» держится по построению, а не тремя аккуратными реализациями.
  ⚠️ Один растеризатор: resvg в WebAssembly (`@resvg/resvg-wasm`) — единственный
  движок, который живёт и в Node, и в браузере. `sharp` больше нет: нативный, 18 МБ
  libvips на платформу, падает под `--ignore-scripts` и за прокси.
  ⚠️ Один шрифт: `assets/inter.ttf`. У WASM-сборки нет доступа к системным
  шрифтам — и это не ограничение, а гарантия: гарнитура из файла, который мы
  везём, поэтому PNG с макбука, из линуксового контейнера и из чужого браузера —
  один и тот же PNG. В экспортируемый SVG вставляется та же гарнитура как
  `@font-face` (woff2-сабсеты по `unicode-range`, 31 КБ на латиницу с кириллицей
  против 343 КБ на всё).
  ⚠️ JPEG кодирует `jpeg-js` из пикселей resvg: resvg отдаёт только PNG, а фон
  берётся `theme.surface` — у JPEG нет альфы, и белый убил бы тёмную диаграмму.
  ⚠️ Проверено байтами, и **тестом, а не на слово**: `test/export.test.ts` в ядре
  держит детерминизм («один растеризатор, один шрифт, никакого состояния
  системы»), а кросс-продуктовую идентичность — `packages/vscode/test/export.test.ts`:
  он гоняет host-бандл и `denji render` на одном документе и сверяет `sha256` по
  всем трём форматам. Жить он может только там: только в расширении есть обе
  половины сразу.
  ⚠️ **Кто рисует — тот и регистрирует, если пришёл не через точку входа.**
  Импорт `@kxchnev/denji` кладёт марки сам; но `cli.ts` ходит по подмодулям (ради
  быстрого `check`), и там загрузчик обязателен: `render` и `watch` зовут
  `loadAssets`. Шрифт и растеризатор не регистрирует за вас никто и нигде —
  `toSvgFile` без `registerFont` отдаст SVG без `@font-face`, `toPng` без
  растеризатора внятно упадёт. Правило: **новый вход, который рисует, начинается с
  загрузчика** (`cli.ts` → `loadAssets`, `vscode/src/assets.ts`,
  `docs/lib/denji-assets.ts`). `denji watch` этот шаг пропустил и отдавал превью
  без логотипов — молча, потому что отсутствующая марка ошибкой не является.
- `src/resources.ts` — реестр больших файлов (`registerIcons`, `registerFont`,
  `registerRasterizer`). Живёт на `globalThis`: у расширения **две** половины
  рисуют, и модульная переменная означала бы два реестра. `src/assets-node.ts`
  (`@kxchnev/denji/assets-node`) — загрузчик для Node; в главный вход не входит,
  потому что тянет `node:fs`, а браузерная сборка на этом ломается.
- `src/render/arch-svg.ts` — SVG-рендер без зависимостей.
  ⚠️ **Режим `plain`** — палитра литералами, без единой CSS-переменной. Для
  растеризатора: resvg роняет объявление, которое не смог разобрать, **вместе с
  фолбэком**, поэтому `var(--x,#eef2ff)` оставляет его вовсе без цвета (замерено:
  вся картинка вышла чёрной). Заодно и цвет наконечника в `<marker>` — это
  атрибут, а не правило, и его тоже надо литералом. В превью режим не годится:
  переменные — это переключение темы без перерисовки.
  ⚠️ **Наконечник назад — нарисован, а не объявлен.** `orient="auto-start-reverse"`
  — это SVG 2, resvg его не умеет и **не жалуется**: маркер рисуется неповёрнутым,
  и в растре все стрелки смотрели вправо. Теперь на цвет два маркера — `-a` и
  зеркальный `-s` с зеркальным `refX`, оба с обычным `orient="auto"`.
  Ломаная рисуется со скруглением (`polyline`): срез угла не больше половины каждого соседнего
  сегмента, иначе тесный зигзаг рассыпается в волну мимо собственного маршрута. Кнопки `@link`
  рисуются **слоем поверх связей**: док коннектора подходит к углу на 10px, а
  кнопка, перечёркнутая стрелкой, перестаёт читаться как кнопка. Хром кнопки —
  `Theme.link`, а не свойства стиля: аффорданс, который автор может
  перекрасить или закрасить, аффордансом быть перестаёт.
- `src/dsl/` — `arch-parse.ts` (парсер `.denji`), `arch-edit.ts` (построчная правка
  объявления — `setNodeRelation`, единственный писатель: драг пишет отношение, а
  не координату. Число строк не меняется, на чём стоит минимальный дифф в
  расширении; там же `findDeclaration` и `findHeaderLine`:
  строка **и колонки** объявления, потому что «где в объявлении лежит id» — факт
  о его форме, а не то, что каждый вызывающий пересчитывает сам; та же
  «объявление — это одна строка», что и у `setNodeRelation`), `error.ts`
  (`DiagramParseError`).
- `src/dsl/arch-parse.ts` заодно экспортирует свой словарь — `SHAPE_KIND_NAMES`,
  `CONTAINER_KIND_NAMES`, `ARCH_OPERATORS` (порядок «длинные вперёд» —
  обязателен), `DIRECTIVE_NAMES`, `ICON_PROP_NAMES`. Это для тех, кому язык надо
  **написать**, а не разобрать (генератор подсветки). `test/arch-vocabulary.test.ts`
  скармливает каждое слово парсеру, чтобы списки не разъехались с реальностью.
- `src/interact.ts` — чистые функции для интерактивного просмотрщика:
  `nodeAt` (хит-тест; фигура берётся целиком, контейнер — только за шапку,
  побеждает самый глубокий), `nodeDepths`, `relationFor`, `isBoxed`, `snapToGrid`,
  плюс ссылки: `linkBadgeRect` (геометрия кнопки `@link` — её же импортирует
  рендер, чтобы «кнопка, которую видно» и «кнопка, по которой попадаешь» были
  одним прямоугольником, а не двумя согласованными вручную), `linkAt` и
  `pickAt` (кнопка всегда бьёт узел: у контейнера она висит в шапке — в
  единственной зоне, за которую его вообще можно взять).
  Живут в ядре, потому что просмотрщиков теперь два (playground и VS Code) —
  повторять эти правила по месту нельзя.
- `src/check.ts` — статические проверки: ошибки парса/build плюс предупреждения
  о раскладке (`hint-cycle`, `overlapping-siblings`, `unconnected-node`,
  `extreme-aspect-ratio`). `loose-node` больше нет: узел без хинтов — обычный
  случай, его ставит граф. Проверку пересечений
  переиспользует `docs/scripts/validate-examples.ts` — не дублировать.
  ⚠️ **Каждая находка обязана знать, где она.** `nodes[]` был там всегда, а
  позиция — нет, и из-за этого предупреждения не могли попасть ни в Problems, ни
  в кликабельный вывод CLI. Теперь `warn()` берёт `findDeclaration(source,
  nodes[0])` и заполняет `line`/`col`/`endCol`/`srcLine`; `extreme-aspect-ratio`
  единственный без узлов — он про рисунок целиком и садится на строку
  `architecture`, где и лежит лечение. Если id не нашёлся — остаются `null`:
  выдуманная позиция уводит читателя не туда с полной уверенностью.
- `src/watch.ts` — живое превью: `node:http` + SSE, следит за **директорией**
  (atomic rename при сохранении убивает file-watcher), держит последний удачный
  рендер и показывает ошибку оверлеем.
  ⚠️ **Это третий просмотрщик, и он тоже отдаёт шрифт.** Гарнитуру сервер берёт
  из реестра (`registeredFonts()`), а не с диска: байты там уже лежат, а превью,
  сходившее за своей копией, могло бы разойтись с тем, что вставляет экспорт.
  Раздаёт на `/font/<n>.woff2` и объявляет `@font-face` в странице — иначе страница
  рисует системной гарнитурой то, что `denji render` рисует Inter, и подписи
  расходятся ровно в том месте, для которого превью и существует.
- `src/cli.ts` — CLI: `render`, `watch`, `check`, `icons`, `spec`. Ассеты грузит
  **только тот, кто рисует**: `render` (по формату — марки, гарнитура, растеризатор)
  и `watch` (марки и гарнитура, без 2.4 МБ WASM). `check`, `icons` и `spec` не
  платят ни за что, поэтому линтер стартует мгновенно.

**Грамматика для моделей.** `packages/core/LANGUAGE.md` — единственный источник
правды по языку (английский), печатается через `denji spec`. `AGENTS.md` в корне
и `.claude/skills/denji-diagrams/SKILL.md` ссылаются на него и несут правила
авторства. При правке `arch-parse.ts` синхронно обновляй `LANGUAGE.md`.

⚠️ Цикл в хинтах теперь идёт в `ArchLayoutOptions.onWarn`; по умолчанию —
`console.warn`, как раньше. `check` подставляет свой сборщик.

⚠️ `node.rect` абсолютный, а `node.local` — та же позиция в пространстве своего
скоупа (каждый скоуп поджат к своему нулю, потом весь рисунок обрамлён). Драг
живёт в `local`: точка броска это `local + delta`, и сравнивать сиблингов можно
только в общем для них пространстве. Заполняется для **всех** узлов. В документ
не попадает никогда — писать координату некуда, драг пишет отношение через
`setNodeRelation` (`src/dsl/arch-edit.ts`), а не сериализацией модели: иначе
форматирование и комментарии автора умрут.

⚠️ Три вещи, без которых драг разъезжается:

1. **Драг не пишет координаты.** Бросок значит «этот встаёт рядом с тем»:
   `relationFor` находит ближайшего сиблинга и сторону, `setNodeRelation` пишет
   `@rightOf(...)`. Координат в языке нет — и это то же самое решение: место,
   записанное числом, верно только для той диаграммы, на которой его измерили.
2. **Документ не перекладывается, пока кнопка нажата.** Иначе якорь скачет, и
   целиться приходится в мишень, которая убегает. На экране — призрак узла и
   подсветка сиблинга, к которому он прицепится; правка одна, на отпускании
   (и один шаг undo).
3. Вид панорамируется в координатах **документа**: раскладка отдаёт
   `diagram.originShift` (сдвиг рамки), а `Diagram` его вычитает. Поэтому сетка
   (`DiagramGrid`) получает чистый `view` и не ползёт, когда рисунок растёт.

### packages/docs (дока)

Next.js App Router + Tailwind + shadcn-компоненты. Ядро подключено как пакет
`@kxchnev/denji` (собранный `dist`) и рендерит диаграммы в браузере. Ключевое:
`components/Diagram.tsx` (parse→layout→render→SVG, pan/zoom; при ошибке парса
держит последний удачный рендер и показывает ошибку оверлеем), `Example.tsx`
(превью + табы DSL/API), `examples/*` (датасет), `app/**/page.tsx` (страницы).

⚠️ Артворк сайт везёт в JS (чанки ~6 МБ): марки приходят с импортом
`@kxchnev/denji`, и это осознанная цена совместимости пакета — см. `NEXT-MAJOR.md`,
там же числа, если решим её не платить. Плюс сайту это даёт то, чего у фетча не
было: страница, отрисованная на сервере, уезжает с логотипами и читается без
JavaScript вовсе. `lib/denji-assets.ts` остался ради двух файлов, которые модулем
быть не могут; кладёт их в `public/denji/` тот же `scripts/copy-agent-files.ts`.
⚠️ Гарнитура и растеризатор ждут первого **скачивания**, и делятся по формату:
SVG нужен только woff2 (31 КБ), растру — ещё outlines и WASM (3.3 МБ). Тянуть
второе ради первого — три с лишним мегабайта за кнопку «SVG». Регистрация при
этом накопительная (`registerAll`): `registerFont` заменяет запись по семейству,
и woff2, зарегистрированный вторым, отобрал бы у растеризатора outlines.
⚠️ `lib/export-diagram.ts` больше не рисует через `<canvas>`: канвас давал
**другую картинку**, чем CLI (свой движок, системные шрифты), плюс лабиринт
фолбэков по размеру канваса. Теперь те же `toSvgFile/toPng/toJpeg` ядра.

Роутинг разделён на две обвязки: `app/(docs)/layout.tsx` — шапка и сайдбар
справочника, `app/playground/` — полноэкранный редактор без них. В корневом
`app/layout.tsx` остаётся только `<html>`, тема и `globals.css`. Плейграунд:
`lib/playground-store.ts` (диаграммы в `localStorage` под одним ключом
`denji.playground.diagrams.v1`, наружу — external store для
`useSyncExternalStore`), `lib/use-playground.ts` (сессия, дебаунс-автосейв,
дип-линк `#<id>`), `lib/playground-templates.ts` (стартовые шаблоны — берут DSL
из `examples/*` **по id**), `components/playground/*` (тулбар, список, пикер
шаблонов).

Правила плейграунда: новая диаграмма сохраняется и появляется в списке сразу,
даже пустая (пустая переиспользуется, а не плодится). `/playground` открывает
последнюю по `updatedAt`, новую заводит только если список пуст; `#<id>` —
конкретную. Удаление мягкое: запись остаётся с меткой `deletedAt`, лежит в
секции «Recently deleted» и вычищается при чтении через `TRASH_TTL_MS` (30
дней); есть восстановление и удаление насовсем (с подтверждением). ⚠️ Записи
идут через внутренний `all()`, а не через `getSnapshot()` — иначе удалённые
затрутся.

Подсветка синтаксиса и автокомплит — на CodeMirror 6: `lib/denji-language.ts`
(токенайзер `.denji`, `StreamLanguage`), `lib/ts-language.ts` (обёртка над
`@lezer/javascript` для API-таба), `lib/denji-symbols.ts` + `lib/denji-complete.ts`
(скан документа и контекстный автокомплит в плейграунде), `lib/editor-theme.ts`
(общая тема редактора). `components/CodeViewer.tsx` — read-only редактор для
статичных примеров (`CodeBlock.tsx`), `components/DenjiEditor.tsx` — редактируемый
для `app/playground/page.tsx`. Палитра токенов — CSS-переменные `--tok-*` /
`--code-*` в `globals.css`, **вне `@layer base`** (Tailwind иначе вычищает эти
классы, т.к. они не встречаются как литералы в файлах из `content`).
⚠️ Токенайзер `.denji` дублирует грамматику ядра — при правках
`core/src/dsl/arch-parse.ts` синхронно обновляй `lib/denji-language.ts`,
`lib/denji-symbols.ts` и `lib/denji-complete.ts` (там же таблица директив с
разрешёнными контекстами и списки значений аргументов — самый большой кусок).

### packages/vscode (расширение)

Живое превью `.denji` как у markdown, плюс драг узлов прямо в файл пользователя.
Две сборки (esbuild, `esbuild.mjs`):

- `dist/extension.js` (CJS, host) — `src/extension.ts` (команды
  `denji.showPreview` / `...ToSide`), `src/preview.ts` (`PreviewManager` — одно
  превью на документ, HTML с CSP, дебаунс 60 мс как в `watch.ts`, сериализатор
  для переживания reload), `src/lens.ts` (CodeLens «Open preview to the side»
  над первой строкой), `src/diagnostics.ts` (`checkDiagram` → Problems, дебаунс
  300 мс — не 60 как у превью: мигающая волнистая линия под недопечатанной
  строкой хуже опоздавшей, и тут полный parse+layout; `nodes[1..]` становятся
  `relatedInformation` через `findDeclaration`; настройка `denji.diagnostics` —
  `all`/`errors`/`off`, потому что предупреждения раскладки эвристичны и спорить
  с ними должно быть можно выключателем), `src/edit.ts` + `src/diff.ts` (запись
  дропа), `src/protocol.ts` (типы сообщений — общие с вебвью).
- `syntaxes/denji.tmLanguage.json` — подсветка. **Генерируется** скриптом
  `scripts/generate-grammar.ts` из экспортов ядра, в гите её нет.
- `dist/webview.js` (IIFE, browser) — `webview/main.ts` целиком тащит `@kxchnev/denji` и
  делает всё: parse→layout→render, pan/zoom/fit, сетка (`webview/grid.ts` — порт
  `docs/components/DiagramGrid.tsx`), хит-тест, драг, оверлей ошибки.

⚠️ Ядро исполняется **в вебвью**, а не в host: драг перекладывает документ на
каждом кадре (иначе контейнеры не растут и связи не перецеливаются), а IPC
round-trip внутри 60fps-цикла заметен. Расширение самодостаточно всё равно —
`@kxchnev/denji` забандлен, у пользователя ничего ставить не нужно.

⚠️ **Экспорт живёт в host, и превью в нём не участвует** (`src/export.ts`,
`src/assets.ts`): правый клик по `.denji` в Explorer пишет PNG при закрытых
редакторах. Раньше это было невозможно: рисовать умела только та половина, что
несла артворк, и это была вебвью. Три команды — `denji.exportSVG|PNG|JPEG`,
подменю `denji.export` в Explorer, в редакторе, в тулбаре превью и по правому
клику в самом превью (для последнего в `<body>` нужен `data-vscode-context`).
⚠️ Марки обе половины получают из **своего** бандла: `@kxchnev/denji` их
регистрирует на импорте, поэтому в `.vsix` артворк лежит дважды и каждый бандл
около 5 МБ (было 231 и 197 КБ, когда марки были файлом). Это цена совместимости
пакета, а не потребность расширения — `NEXT-MAJOR.md` описывает, как её вернуть.
Файлами остались только гарнитура и растеризатор в `dist/assets/` (копирует
`esbuild.mjs`), их читает host; вебвью из них берёт `@font-face` — отсюда
`font-src ${webview.cspSource}` в CSP, единственное новое разрешение, и только к
своим же файлам.

⚠️ Дроп пишется **построчным диффом** (`src/diff.ts` → `WorkspaceEdit`), а не
заменой всего документа: `setNodeRelation` переписывает объявление на месте и
никогда не меняет число строк, поэтому сопоставление по индексу точное — и
курсор, выделение и свёрнутые блоки автора остаются на месте. Один `applyEdit`
на дроп = один шаг undo. Источник берётся из `document.getText()` в момент
коммита, а не из копии вебвью (пока тянут узел, в редакторе могли печатать).

⚠️ Дроп передаётся как `{ id, anchor, side }`, а не как координата
(`src/protocol.ts`): вебвью решает, к кому узел прицепился, host это записывает.

⚠️ Подсветка **не написана руками** — шестой копии грамматики в репозитории нет.
`scripts/generate-grammar.ts` берёт слова из ядра (`SHAPE_KIND_NAMES`,
`CONTAINER_KIND_NAMES`, `ARCH_OPERATORS`, `DIRECTIVE_NAMES`, `ICON_PROP_NAMES`,
`STYLE_PROPS`, `CORNERS`, `themes`), а формы строк — из самого скрипта, потому
что TextMate умеет только регэкспы. Добавил вид фигуры или директиву в ядро —
подсветка узнает о ней на следующей сборке. Регистр: виды фигур ядро сверяет
буквально (`App` — не вид), а имена директив и свойств прогоняет через
`normalizePropName` — отсюда `alt` против `altI` в генераторе.
⚠️ `test/grammar.test.ts` гоняет реальный движок (`vscode-textmate` +
`vscode-oniguruma`) и проверяет **скоупы токенов**. Проверять, что нужные слова
«есть в JSON», бесполезно: так и было, пока подсветка не работала вовсе.


## Команды (из корня)

- `npm run build` — собрать ядро (`packages/core/dist`) и расширение
- `npm test` / `npm run typecheck` — тесты/типы ядра и расширения
- `npm run docs` — dev-сервер доки **плюс** `tsc --watch` ядра (правки core
  подхватываются без рестарта); `npm run docs:build` — статический экспорт.
  ⚠️ «Без рестарта» — про **тела функций**. Next кеширует граф модулей пакета, и
  правка, которая меняет *форму* ядра — новый или убранный экспорт, побочный
  эффект на импорте, — живым сервером не подхватывается: `tsc --watch` перепишет
  `dist`, а страница продолжит крутить старый модуль. Симптом обманчивый: всё
  собирается, тесты зелёные, а в браузере пусто (в нашем случае — плейграунд без
  логотипов). Лечится рестартом `npm run docs` и жёстким релоадом; заподозрить
  стоит сразу, как только правка тронула `src/index.ts` или `package.json` ядра.
  ⚠️ Dev-сервер работает в **своей** директории `.next-dev`, а сборка — в `.next`
  (`next.config.ts`, по фазе). Иначе `next build` при живом `next dev` затирает
  его чанки, и сервер падает на `Cannot find module './NNN.js'` до перезапуска.
  Двигать пришлось именно dev: при `output: "export"` кастомный `distDir` уносит
  не рабочие файлы сборки, а выгруженный сайт — `server/` всё равно ложится в
  `.next` (проверено тремя способами). Второй dev-сервер поднимать со своим
  `NEXT_DIST_DIR`.
- `npm run -w docs validate` — прогнать все примеры доки через ядро
- `npm run vscode` — пересборка расширения по изменениям; F5 (`.vscode/launch.json`)
  открывает Extension Development Host на `packages/vscode/examples/sample.denji`
- `npm run vscode:package` — `.vsix`
- `npm run vscode:install` — собрать `.vsix` и поставить его **локально** во все
  найденные редакторы (`code`, `code-insiders`, `cursor`, `windsurf`) вместо
  версии из Marketplace: та всегда та, что опубликована последней, и пока она
  стоит, редактор грузит её, а не то, что ты правишь. `--force` заменяет её даже
  при том же номере версии — а он посреди работы обычно тот же.
  ⚠️ Marketplace отыграет обратно, как только опубликует версию выше:
  чтобы локальная сборка осталась, у расширения нужно выключить Auto Update.
  `npm run vscode:uninstall` — снять её и вернуться к опубликованной.
- ⚠️ **Версии и совместимость — три правила, и они не обсуждаются по ходу дела.**
  1. **Ломать совместимость нельзя**, пока владелец репозитория явно не решил
     выпускать новый мажор. Любая правка — обратно совместимая, чего бы это ни
     стоило по размеру бандла, скорости сборки и красоте кода. Работающий код
     потребителя важнее нашего удобства; «никто этим не пользуется» — не аргумент,
     потому что проверить это нельзя.
  2. **Всё, что хочется сломать, пишется в `NEXT-MAJOR.md`** — что убрать, почему
     отложено, что сломается у потребителя, что мы получим взамен (числами). Файл
     читается целиком в день, когда решено поднимать мажор; ничего не теряется и
     ничего не делается втихую.
  3. **Ядро и расширение релизятся под одним `major.minor`.** Различаться могут
     только патчи: `core@1.2.3` и `vscode@1.2.0` — норма, `core@1.3.0` и
     `vscode@1.2.0` — нет. Расширение везёт движок внутри `dist/webview.js`, и
     «какая там версия denji» должно читаться по номеру, а не по дате сборки.
     Значит минор поднимается **обоим** пакетам, даже если один из них не менялся.
- `npm run release:core <версия>` / `npm run release:vscode <версия>` — поднять
  версию пакета (и лок вместе с ней). Больше ничего не нужно:
  `.github/workflows/release.yml` на push в `main` видит, что такой версии нет
  снаружи, публикует — ядро в npm, расширение в Marketplace, — ставит тег
  `core@<версия>` / `vscode@<версия>` и заводит Release (у расширения с
  приложенным `.vsix`). Пакеты независимы: подняли одну версию — уехал один.
  ⚠️ Решает **реестр**, а не дифф: npm спрашивается через `npm view`, Marketplace
  — через gallery API. Перезапуск, revert и повторный push одного коммита тогда
  не публикуют дважды. `vsce show` для этого негоден: на несуществующем
  расширении печатает `undefined` и выходит с кодом 0.
  ⚠️ Правка версии руками ломает `npm ci`: лок хранит версию воркспейса, а
  расходится он молча — до самого CI.
  ⚠️ Changelog-файлов нет: заметки релиза — это subject'ы коммитов, отобранные
  **по границе артефакта**. У ядра это `packages/core`; у расширения — ещё и
  `packages/core`, потому что `.vsix` несёт движок целиком в `dist/webview.js`.
  Значит, сообщение коммита читают в списке и без диффа — пиши соответственно.
  ⚠️ Тег и Release ставит общий composite-шаг
  `.github/actions/tag-and-release`, а не каждая джоба сама: логика поиска
  предыдущего тега по своему префиксу и фильтра по путям слишком тонкая, чтобы
  жить в двух копиях.
  ⚠️ У npm секрета нет вовсе — Trusted Publishing по OIDC, привязка к **имени
  файла** `release.yml`. У Marketplace OIDC тоже есть (Entra ID + managed
  identity + `--azure-credential`), но здесь выбран `VSCE_PAT` — единственный
  секрет репозитория. Токен обязан быть **org-scoped**: глобальные заблокированы
  с марта 2026 и отключаются 1 декабря, так что у этого секрета есть не только
  срок жизни, но и дедлайн.

## Конвенции

- ESM, `NodeNext` в ядре. Импорты локальных модулей ядра — с расширением `.js`.
- `strict` + `noUncheckedIndexedAccess` в ядре. Раскладка детерминирована.
- Дока и расширение цепляются к **собранному** `@kxchnev/denji` → после правок ядра
  `npm run build`. Исключение — работающий `npm run docs`: он держит свой
  `tsc --watch` и пересобирает ядро сам; расширению сборка нужна по-прежнему.
  Тесты расширения гоняют реальный `dist/webview.js` в jsdom,
  так что сборка входит в `npm run -w packages/vscode test`.
